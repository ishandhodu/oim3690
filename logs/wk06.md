## Predict Before You Delete

**Line 1 (an `addEventListener`):** `form.addEventListener('submit', (event) => { ... });` in `js/todo.js`
- Predicted: without this, clicking "Add Task" would do the browser's default form submit — the page would reload/navigate instead of adding the task.
- Actual: I was right that the task never got added, but for a bigger reason than I expected. Commenting out only the opening line left the rest of that block (`event.preventDefault(); ... });`) sitting outside of any function — and one of those lines uses `return` outside a function, which JavaScript doesn't allow. That's a syntax error, which stopped the entire `todo.js` file from running at all, not just the submit handler. The DevTools console showed a red error confirming it.

**Line 2 (a line that changes the page):** `list.appendChild(item);` in `renderTodos()`
- Predicted: tasks would still be added to the `todos` array and saved to `localStorage`, but nothing would ever show up on screen — the list would look permanently empty.
- Actual: Confirmed exactly as predicted. The task never appeared in the visible list, but checking DevTools → Application → Local Storage showed the `todos` key still had the new task saved — the data was fine, it just never got drawn onto the page.

**Line 3 (my choice):** `saveTodos();` inside `addTodo()`
- Predicted: new tasks would show up normally while the page is open, but they would vanish after a refresh since they were never written to `localStorage`.
- Actual: Confirmed exactly as predicted. I added three tasks and they all showed up fine, but refreshing the page wiped all three — they were only ever held in memory, never written to `localStorage`, so the page had nothing to reload them from.
